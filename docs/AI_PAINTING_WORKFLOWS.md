# AI 绘画场景与多模型工作流规划

需求同步与资料核对日期：2026 年 10 月 20 日。本文补充 [产品需求](PRODUCT_REQUIREMENTS.md) 的 AI 辅助范围，供 Windows 服务与 Mac 原生客户端共同实现。

用户要求按绘画场景选择多种模型和工作流，明确包含线稿绘制与完善、线稿上色、灰稿二分明暗与四档明度、光照、场景绘制和人像精修。下文另外补充材质、角色一致性、局部修复、素材提取、扩图与放大等候选场景；这些补充与开发顺序是实施建议，不代表已经交付。

产品入口采用“绘画用途 → 可用工作流 → 兼容模型与参数”。同一模型可以服务多种用途，同一用途也可以比较不同模型；界面只列经过兼容性核验的组合。

## 当前可用能力

现有真实预设 `paint-edit-v1` 使用 FLUX.2 Klein 4B FP8，配套 `qwen_3_4b` 文本编码器和 `flux2-vae`，4 步采样，内部约 1MP 后恢复到原裁切尺寸。模型接收参考图和文字，返回后由桥接应用原灰度选区作为透明度。**它是参考图编辑后限制回填范围，不是模型原生蒙版重绘。** 实现见 [预设目录](../ipad_bridge/bridge/presets/manifest.json) 和 [工作流](../ipad_bridge/bridge/presets/paint-edit-v1.json)。

桥接目前只公布一个真实预设，iPad 默认选择能力列表的第一项。单次任务只保存第一张输出，结果尺寸回到原裁切。因此，多模型选择、多参考输入、批量候选、真正超分和画布外扩图均需相应实现，不能只添加模型文件或更换提示词就标为完成。

## 绘画场景清单

所有生成结果先进入候选区，确认后作为可撤销的新图层加入；原稿、原线稿和已有图层保留。表中输出均是目标行为。

| 场景 | 输入和操作 | 期望输出与验收重点 |
| --- | --- | --- |
| 线稿清理 | 草稿、扫描线稿或当前线稿层；指定需清理区域 | 去杂线、统一线条、清理底色；与允许改结构的完善功能分开；保留原线稿供比较 |
| 草稿完善与补线 | 草稿、结构参考、选区；选择保守补充或允许重新设计 | 完整轮廓和细节线稿候选，能检查是否改动姿态、比例和设计；不能把边缘提取等同于理解结构后补线 |
| 线稿铺底色 | 独立线稿及可选色块、调色板或配色参考 | 少阴影的底色候选，可置于原线稿下面；不能承诺自动得到按皮肤、衣服、头发拆好的可编辑图层 |
| 线稿完整上色 | 线稿、风格参考、配色和明暗说明 | 带体积与阴影的完成度候选；提供结构约束和改动强度，比较不同画风 |
| 灰稿二分明暗 | 已有灰稿，或尚未充分塑造的体块草稿 | 明暗两大块。明度分阶与 AI 重新安排光影分成两个操作，后者可能改变阴影位置 |
| 灰稿四档明度 | 灰稿或二分结果；选择四个明度值与阈值 | 四档明度设计稿。可设暗、次暗、次亮、亮的值，不把四档明度强行等同于四种物理光照成分 |
| 灰稿上色与配色变体 | 灰稿、调色板或色彩参考 | 保留明度关系的不同色彩方案；另提供允许调整明暗的模式，避免把两种需求混在一起 |
| 光照设计 | 原图、指定人物或物件、光源方向与软硬；后续支持光照参考 | 顶光、侧光、逆光、冷暖和时间气氛候选；人工比较体积、投影与背景是否一致 |
| 场景与背景 | 构图草图、透视线、色块或 3D 白模截图；保护主角区域 | 场景草案、背景补全、天气与时间变体；保持视平线、空间关系和主体轮廓 |
| 人像精修 | 人像局部、明确修改部位、低改动强度；可选人物参考 | 皮肤、头发、眼睛、服饰与光照细节候选；默认保留原人物特征，不能把人脸恢复当作身份绝对一致 |
| 局部结构修正 | 手、五官、衣褶、透视或遮挡区域；可选姿态参考 | 仅选定部位的结构候选；保留上下文，不能保证自动符合全部解剖与透视要求 |
| 材质与细节 | 选定布料、皮革、金属、玻璃、木材、石材等区域 | 材质替换、磨损和纹理候选，保持物体轮廓与原有光照意图 |
| 角色与系列一致性 | 同一角色的设定图、服饰配色、风格参考 | 连续画面中的角色、服装和配色尽量一致；先支持参考图，再评估专用 LoRA |
| 清除与背景修补 | 待清除物体、杂物或污点的蒙版及周边上下文 | 局部修补候选；原生蒙版工作流与现有生成后裁切工作流分别标注 |
| 素材提取与蒙版辅助 | 人物、头发、道具或背景图像 | 透明素材或可编辑蒙版；边缘和半透明区域可复核。它不一定需要扩散生图模型 |
| 构图与创意探索 | 草图、关键词、主体参考 | 多种镜头、构图、服饰或道具设计候选；明确这是允许较大改动的探索模式 |
| 扩图与画布补全 | 原画、目标画布尺寸、扩展方向 | 画布外新内容与正确位置，扩画布和加入结果一起可撤销；需要扩展几何协议 |
| 放大与成稿整理 | 当前画稿、目标尺寸，选择保真或创意细化 | 保真放大与重新补细节分开；真正输出更大图像，不在服务末尾缩回原尺寸 |

### 二分与四档明度的具体含义

用户已确认这里指绘画中的二分明暗和四档明度。

“明度归纳”使用明确的阈值或分阶算法：不重绘形体或重新安排阴影，将明度归纳为指定的两档或四档，提供可调整阈值与预览。这类基础工具宜在 iPad 离线可用；Windows 工作流可使用相同规则处理 AI 输出。精确分阶的像素值与软选区边缘回贴分别验收。

“AI 明暗设计”根据灰稿、光源与体积要求重新提出明暗安排，再按需要分阶。它适合未画完阴影的草稿，但不能只靠提示词保证严格只有两档或四档数值，也不能将生成的光影解释成真实三维计算。

## 模型与工作流分工建议

| 路线 | 建议角色 | 接入条件与边界 |
| --- | --- | --- |
| FLUX.2 Klein 4B | 保留现有快速编辑；优先测试配色、材质、场景和明暗方案 | 官方支持生成、编辑和多参考；4B 使用 Apache 2.0。多参考是模型能力，当前桥接还只有单图输入。见 [官方模型卡](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B) |
| SDXL 加结构控制 | 新增线稿完善、保结构上色、姿态和透视约束路线 | 评估匹配 SDXL 的 MistoLine 或 ControlNet Union，选择具体兼容基础模型并实测。ControlNet 是结构控制组件，不能当作独立生图模型，也不能直接与 FLUX 或 Qwen 混用。见 [MistoLine](https://huggingface.co/TheMistoAI/MistoLine)、[ControlNet Union](https://huggingface.co/xinsir/controlnet-union-sdxl-1.0) |
| 专用蒙版重绘 | 局部修手、五官、清除物体和材质替换 | 采用与基础模型匹配的蒙版条件与编码流程；模型使用蒙版和结果按选区回贴是两件事，均需独立验证 |
| IC-Light | 人物或物件的专用换光与背景光照匹配 | 原作者提供前景条件和前景加背景条件路线；作为独立工作流包验证，不直接替换现有 FLUX 节点。输出是重打光图像，不能自动当成物理正确的独立光照层。见 [原作者项目](https://github.com/lllyasviel/IC-Light) |
| Qwen-Image-2.1 | 可选研究评估包，测试复杂指令、多参考与透明素材 | 官方模型卡列出这些能力；16GB 上仍需验证量化、编码器卸载、输入尺寸与耗时。该版本采用研究许可证，商业用途需另取许可，因此不默认用于接稿生产。见 [模型卡](https://huggingface.co/Qwen/Qwen-Image-2.1)、[许可证第 2 节](https://huggingface.co/Qwen/Qwen-Image-2.1/blob/main/LICENSE) |
| 线稿提取、分阶、分割与超分工具 | 辅助准备输入和整理输出 | 按任务选择传统图像处理或专用模型；不会因不使用扩散模型而被排除在工作流目录之外 |

Qwen 2.1 的提示词增强器与图像生成所需文本编码器不是同一组件，完整依赖按 [Comfy 官方模型包](https://huggingface.co/Comfy-Org/Qwen-Image-2.1) 核对。文件存在、预检通过、实际生成成功和适合画稿使用应分别记录。带区域标记的参考图编辑，也不能直接标为原生蒙版条件生成。

模型包记录确切来源、版本、量化方式、许可证、所需节点和已测试尺寸。SDXL 基础模型、ControlNet、LoRA 和参考图适配器的条件分别核对，不从一个组件的许可推导整套模型的许可。先建立少量可用组合，不把未测试模型一并开放给客户端。

目标硬件先按单张 16GB NVIDIA 显卡设计：单个生成任务排队，模型按需加载，优先选区裁切与约 1024 档测试。记录冷启动、模型切换、热生成、峰值显存和主机内存；不预设所有模型可同时驻留，也不承诺未测的 2K 多参考速度。

## iPad 使用流程与两端分工

建议流程：选择画面或图层与作用区域 → 选择用途 → 选择可用模型档位 → 添加必要参考 → 设置保结构程度与改动强度 → 生成候选 → 对比后加入新图层。

默认显示用途和适用说明，模型名称与版本可展开查看，也允许高级用户在该用途的兼容模型中选择。缺模型或缺节点的工作流显示原因。相同模型的提示词模板可以作为便捷入口，但不能标成多模型支持；只有连接了不同可运行模型包才计为多模型交付。

| Windows 负责 | Mac 与 iPad 负责 |
| --- | --- |
| 工作流注册、模型依赖检查和逐项可用状态 | 用途与模型选择器，连接旧服务时保留原入口 |
| 模型切换、单 GPU 队列、任务持久化和错误原因 | 图层、选区、参考图选择，明确哪些内容发送到 Windows |
| 模型需要的结构图、蒙版转换及结果处理 | 同一裁切下的画面、线稿和蒙版坐标对齐 |
| 冻结任务的模型、参数、工作流版本和输入 | 发送前保存不可变提交快照，切文稿后不错误应用结果 |
| 输出图像、位置、透明度与来源记录 | 候选对比、加入新图层、撤销与保存；精确线稿保留在原层 |

参考图按角色区分：画面、线稿、编辑蒙版、色块、配色参考、风格参考、人物参考、深度或姿态。线稿和深度图属于有画布坐标的结构输入，风格或人物参考可以是独立尺寸。第一阶段先支持原有画面加蒙版；需要额外输入的用途保持未就绪状态，等待双方完成协议扩展。

## Windows 实现边界

### 第一阶段兼容现有客户端

1. 用一个注册表统一 `capabilities`、请求校验、预检和工作流加载；保留 `paint-edit-v1` 的名称标识与旧默认行为，旧客户端继续使用它。
2. 每个工作流公布可读名称、用途、固定模型组合、版本、输入要求、尺寸限制、可调整参数与可用状态。一个未安装工作流不能导致其他可用工作流失效。
3. 新客户端先仅选择已有字段 `workflowPreset`。新增能力字段采用可选字段；无参数的后端状态检查仍检查默认预设。新客户端按所选预设检查就绪状态，不能因默认模型缺失而阻塞其他可用预设。
4. 接收新任务时冻结解析后的工作流、参数和模型版本；保存图内容，或让摘要指向仍保留的不可变版本，并记录必要模型标识及输入哈希。版本缺失时明确失败，不能按新目录重新解释旧任务。相同种子不承诺跨硬件逐像素复现。
5. 保留既有重复请求校验、删除墓碑及未知提交结果恢复行为；重启或断网后不能盲目创建第二个 GPU 任务。数据迁移需兼容已有任务。

当前关键入口是 `bridge/config.py`、`bridge/images.py`、`bridge/app.py`、`bridge/comfy.py` 与 `bridge/presets/`。客户端 `EditorBridge.swift` 直接使用首个预设，需改为明确选择。具体字段在实现 PR 中同步更新 [API v1](../ipad_bridge/docs/API_V1.md)，本规划不冒充已发布协议。

### 需要另行扩展的能力

- 多参考图和自由参数：现有请求严格拒绝未知元数据字段，必须先进行能力协商。新增文件和参数纳入持久化、大小限制和重复请求校验。
- 原生蒙版工作流：模型端蒙版约定逐项转换，原始灰度选区单独保留用于回填；避免将同一软边连续相乘。需要上下文裁切时统一记录坐标。
- 多张候选与有角色的输出：当前 worker/store 只取并保存第一张输出，需要改为结果集合。生成“底色层、阴影层”等必须经过专门验证，不能将一张成图称为真实分层结果。
- 真正放大与画布外扩图：现有结果缩回原裁切，裁切必须位于原画布。需新增输出尺寸、放置位置、目标画布及可撤销客户端事务，保留旧任务语义。
- 第三方节点：现有 ComfyUI 启动辅助程序禁用自定义节点。先选原生节点方案；需要第三方节点时在隔离环境固定版本、测兼容后明确启用，不能仅下载模型后宣称工作流可用。

## 开发顺序与验收

| 顺序 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 1 | 多工作流目录、独立预检、任务版本冻结，iPad 选择器 | 旧配对和旧任务继续可用；同一原稿可选择两个不同模型组合；缺依赖只影响对应项；切模型、重启和重试不丢任务或重复生成 |
| 2 | 第一批绘画工具：线稿完善、线稿上色、二分与四档明度、灰稿配色、通用场景参考 | 用固定测试画稿比较保线、配色、明度与改动范围；原图保留，候选在正确位置回填并能撤销 |
| 3 | 原生局部重绘、专用光照、人像与材质精修、多参考输入 | 单独验证蒙版条件、边缘融合、人物特征和参考图角色；对每个模型记录目标机器的质量与运行成本 |
| 4 | 多候选比较、角色一致性扩展、透明素材、真正超分与画布外扩图 | 输出集合、透明度和几何事务均有测试；扩图后保存重开、撤销和恢复正确；旧客户端按能力降级 |

首批样例采用合成或获准的测试素材，覆盖干净线稿、杂乱草稿、平涂灰模、已有明暗灰稿、人像局部、衣物材质和场景透视稿。逐项记录：输入与目标、模型版本、参数、生成耗时、显存与内存、选区外保护、线条或身份偏移、候选可用性。模型成功返回图片只算执行通过，画稿用途仍需用户判断。

本轮交付是需求和实施规划；新增模型包、节点和客户端能力在后续实现中分别验收。
