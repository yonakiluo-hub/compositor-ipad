| 顺序 | 内容 | 接手时状态 |
| --- | --- | --- |
| 1 | 剪贴蒙版、组内整理、组蒙版、多层共同变换 | **剪贴已实现，用户确认剪贴、撤销和重开正常**；后面三项尚未完成。已有多选与受限合并不等于多层共同变换。 |
| 2 | 曲线、色阶、可再次编辑的调整层 | 尚未实现；现有亮度、对比度、饱和度和模糊是可撤销的像素修改。 |
| 3 | 笔刷预设与手感、渐变、仿制、修复 | 已有基本 Pencil 输入；这些扩展仍需开发及真实绘画验证。 |
| 4 | 魔棒与自动选取、选区扩缩、透视和扭曲 | 已有套索、组合、羽化及单层/选中像素自由变换；本行扩展尚未实现。 |

## 建议交给下一个 agent 的首个子功能：组内整理

建议范围为已有图层移入/移出组、多选创建组及明确的同级插入位置。已有单层同级排序继续复用。先核对上游 `LayerGroups.swift` 的操作与次序，再接入当前文稿事务；具体支持范围应在实现前写清楚。

- 入口：`ipad_app/Sources/Core/DocumentEditor.swift`、`Core/LayerGeometry.swift`、`App/EditorLayers.swift`、`App/EditorView.swift`。现有 `moveLayer(_:into:)` 仅处理单层父组变化，不能用循环调用来代替整批原子移动和目标位置计划。
- 保留文稿及图层 UUID、原 PNG、独立蒙版、变换、层序和剪贴关系。嵌套组后代去重，禁止移入自己或后代；锁定/隐藏项与目标组的处理必须明确。
- 剪贴只支持同父组连续普通栅格层、直接引用基底的 `maskSourceID`。完整堆栈应能作为一个操作对象规划；会拆散依赖的移动应整次拒绝，不能先写出无效中间状态或偷偷释放剪贴关系。
- 在所有检查通过后一次提交；失败保留原稿，撤销一次恢复原父组和次序，重做与保存重开保持一致。选择状态属于导航，不应独立污染文稿历史。
- 回归至少覆盖嵌套组、完整剪贴堆栈、不完整依赖、锁定/隐藏项、组内上下遮挡、原子失败和工程重开，再进行真实界面操作验证。跨父组移动会改变祖先透明度/显示条件，不能笼统承诺画面恒定；需要明确规则和相应测试。

## 后续核心边界

| 子功能 | 开发前需要处理的边界 |
| --- | --- |
| 组蒙版 | 当前模型校验拒绝组携带蒙版，渲染采用穿透组。先定义组蒙版、组透明度、混合和剪贴的合成次序，再一起扩展模型、读写、渲染、预览和合并。对每个子层分别乘蒙版通常不等于给组合成结果乘一次。 |
| 多层共同变换 | 扩展冻结的选择集合、后代去重、统一枢轴、迟到手势保护和单次事务；明确有选区时作用于哪些像素。现有变换只有位移、尺寸、旋转和翻转，旋转层共同非等比缩放可能产生剪切，不能静默丢弃。 |
| 曲线/色阶/调整层 | 复用上游参数与 LUT 算法，保留 alpha；参数、影响范围、蒙版、预览、撤销与持久化同时落地。当前读取器拒绝 `adjustment` 记录，不能只加面板或覆盖源像素就宣称可再次编辑。 |

官方上游核对基线为 `365b5745eda537f984f3d5bed1e53c361dbc9c91`，早期中文分支为 `7c2a5a4a3e7f685a8a0ec282ef0b4284f20b5477`；来源、具体文件和差异见移植清单。选定复用代码时重新核对其格式及依赖，保留 MIT、NOTICE 和来源；AppKit 交互需适配 UIKit/Pencil。

## 不能回退的行为

- 文稿变更通过 `DocumentEditor.transaction` 等统一入口；未完成预览不修改已提交文稿。切文稿、工具、目标或后台后，过期手势不能提交到新状态。
- 选区保存为数值灰度覆盖；软边在各操作中按定义使用，不能误把明确的全黑选区当作无选区。整层变换和选中像素变换的蒙版处理规则不同，延续现有测试。
- `.comp` 保存原层资源与可编辑结构；未知格式内容明确拒绝，禁止静默压平或删除。iPad 状态绑定清单摘要；保存、归档与重开必须同步验证。
- AI 上传已提交文稿外观，固定原图、L8 mask、描述、预设和请求 ID；未知提交按原字节恢复。候选按原裁切坐标作为新层加入，已应用的选区 alpha 不再乘第二次；文稿变化后的旧候选必须确认。
- 本地编辑不依赖 Windows。当前 4096 单边/1600 万像素面限制与内存保护不代表大画稿性能已验收，不能为了跑通样例直接取消。

1. 按客户端 README 检查 Xcode、SDK 和可启动的 iPad 模拟器。新增/删除 Swift 文件后运行 `python3 ipad_app/tools/generate_project.py`，提交生成的工程；模拟器保留 ad-hoc 签名以支持 Keychain。
2. 核心用 `swift test --package-path ipad_app`，原生与 UI 用 `bash ipad_app/tools/verify_ipad.sh <iPad-simulator-UUID>`。应创建隔离测试模拟器和合成画稿，避免测试重置用户日常数据。新逻辑有代表性回归通过后再跑适用的完整检查。
3. 未配置 HTTP 测试环境时有 3 项测试跳过；不能把它记成网络测试通过。网络改动用独立 mock 和合成文件验证，环境变量见 `Tests/BridgeTests.swift`；不要默认使用真实配对触发 GPU 或候选删除。
4. 本机此前已经完成 Xcode 账号、开发签名及原 iPad 安装授权，基础应用也已被用户信任。接手时先检测可用状态，不必从头要求用户登录或重建证书；若确有缺失再说明。继续沿用原应用标识覆盖安装，保留数据，不为解决测试问题卸载用户应用。
5. 配对、签名、用户画稿、生成结果、模型与数据库不进仓库。实际路径、Team ID、设备 ID 和令牌通过本机检查或私下交付取得，不写入公开交接。
