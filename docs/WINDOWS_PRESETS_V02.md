# Windows 多预设增量 v0.2

本增量保留 V1 的单图、单蒙版、单候选与原坐标新图层流程，在已有桥接上增加预设目录、入队执行快照、依赖身份核验、队列预算和持续推理占用保护。它不是 Windows 绘图编辑器，也不表示需求 v0.2 中所有绘画场景已经通过质量验收。

## 本次交付与边界

| 内容 | 实现与限制 |
| --- | --- |
| 共享预设目录 | 验证、能力描述、图加载和结构预检使用同一白名单；默认 Klein 始终在第一位 |
| 多模型固定组合 | 可选择明确版本的预设，不提供模型与工作流任意组合；Qwen 两项为默认关闭的实验预设 |
| 入队冻结 | 保存图、参数、seed、几何、输入摘要、权重 SHA-256、源码及运行依赖证据；执行前重新核验 |
| 任务与恢复 | 沿用现有 SQLite 队列、原始字节幂等和墓碑；不另建任务状态机，不自动重发未知提交 |
| 资源保护 | 默认最多 8 个待处理任务、256 MiB 待处理规范化输入；超时不代表显卡空闲 |
| 结果契约 | 原 crop 尺寸、单 `results/0`、straight alpha，模型输出 alpha 与选区 mask 只乘一次 |
| 小样评估 | 已提供可复现合成样本工具；每个模型的 GPU、资源与视觉验收须独立记录 |

线稿上色、草图细化、局部修补、明度与光影是首批评估切片；它们仍使用参考图编辑加输出遮罩。扩图、超分辨率、多参考、多候选、原生蒙版条件、取消和自动缓存淘汰未在本增量开放。严格二阶/四阶量化与艺术化明暗生成分开，基础量化留给 iPad 离线实现。

## 固定预设

| 预设 ID | 模型与采样 | 输入边界 | 默认状态 |
| --- | --- | --- | --- |
| `paint-edit-v1` | FLUX.2 Klein 4B FP8，4 steps，约 1MP 推理后还原 crop | 最短边 16，长宽比 ≤16，最多 4,194,304 像素 | 开启、默认首项 |
| `qwen21-edit-v1` | Qwen-Image-2.1 INT8 ConvRot + Qwen3-VL 8B + BF16 VAE，25 steps | 最短边 32，长宽比 ≤4，最多 1,048,576 像素 | 实验关闭 |
| `qwen21-turbo-edit-v1` | 上述基础组合 + 官方 Turbo LoRA，8 steps，固定 sigma 序列 | 同 Qwen 基础版 | 实验关闭 |

Qwen 两项的模型许可将非商业用途限定为研究或评估，商业使用需另获许可；启用实验开关不授予商业权利。[基础模型许可](https://huggingface.co/Qwen/Qwen-Image-2.1/blob/main/LICENSE)、[Turbo 许可](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo/blob/main/LICENSE)。模型权重不随仓库发布，已有文件也不代表兼容或能装入显存。具体图来源、节点版本及评估命令见 [Qwen 实验记录](QWEN_EXPERIMENT.md)。

## Windows 配置

真实后端新增 `--comfy-models-dir` 与 `--comfy-install-dir`。这两个目录必须对应正在连接的 ComfyUI 实例，不能指向一份名字相同但未实际运行的源码或权重副本。入队时核验运行参数、权重字节、核心节点源码和运行依赖版本；首次读取大权重摘要可能使首个新任务等待较久，接口重试必须保持同一请求 ID 和原文件。

以下均为示例路径，在 `ipad_bridge` 目录执行时替换为本机实际位置：

```powershell
python -m bridge serve --backend comfyui --data-dir data-comfyui --comfy-url http://127.0.0.1:8388 --comfy-models-dir D:/ExampleModels --comfy-install-dir D:/ExampleComfyUI --host 127.0.0.1 --port 8190
```

需要本地研究评估时显式加 `--enable-experimental`。`--max-pending-jobs` 默认 8，`--max-pending-bytes` 默认 268435456；它们仅限制排队/运行任务及其规范化输入，不是历史缓存总量或实际显存配额。ComfyUI 本身保持仅回环地址访问；iPad 连接桥接的局域网地址，沿用原私有配对与令牌。

受控 ComfyUI 实例应使用本项目 `tools/start_local_comfy.py`：明确模型根目录，禁用全部第三方节点和 API 节点；不使用额外模型搜索配置或其它目录覆盖来绕过摘要核验。新模型需要更高版本核心节点时，先准备独立安装与运行目录、固定版本并验证，不能在正在画画的旧实例上全局开启第三方节点。此服务不接受客户端传入脚本、任意工作流或模型下载地址，不自动安装节点或权重。

本版本还核对本机端口对应的进程、完整启动参数和启动时间。修改权重或 ComfyUI 源码后必须先重启 ComfyUI；文件晚于进程启动时将拒绝新任务，防止读取旧缓存。代理转发、远程 ComfyUI、无法读取进程信息的运行账户不属于本版本支持范围。`start-bridge.ps1` 支持 `-ComfyModelsDirectory`、`-ComfyInstallDirectory` 和 `-EnableExperimental`。[PR4 的启动器兼容修复](https://github.com/yonakiluo-hub/compositor-ipad/commit/59f4e65) 会根据本机桥接是否支持，自动从原配置传入两个目录；未包含该修复的旧启动器需要先更新。启动器不会自动开启实验预设。

## 任务冻结与显卡占用

客户端仍上传 V1 的 image、mask 和 metadata，通过已有 `workflowPreset` 选择固定组合。202 返回前完成执行快照持久化。后续更新预设文件不会改变已排队任务；模型、源码或运行依赖变动时，旧任务明确失败，不改用新模型、默认种子或较小分辨率。

执行快照同时在私人数据中冻结 `comfyOrigin`，推理占用绑定接受该提交的 ComfyUI endpoint。修改连接地址不会把旧任务转移到新服务：尚未提交的任务明确报 `backend_changed`；已提交的任务保留原状态，等待恢复原连接后对账。占用地址与当前连接不一致，或旧占用没有地址记录时，不查询当前实例来判断旧 GPU 是否空闲，也不自动释放占用。状态接口返回 `ok=false` 和 `executor_connection_mismatch`，不暴露原始地址。应恢复原连接；必须人工恢复时，先确认原执行实例已重启，操作工具仍会拒绝用不同地址释放已绑定占用。

客户端原始 PNG 字节仍用于幂等摘要；规范化后的图像摘要另用于执行前核验。相同请求重放先查原记录，故队列满、模型离线或预设关闭都不影响已有任务查询；内容不一致为 409，已删请求为 410。新请求受预算限制时返回 429 和 `Retry-After: 5`。

桥接串行提交，并在 `/prompt` 副作用之前持久记录推理占用。任务超时后可能已经向 iPad 报告失败，但占用仍保留；即使删除该候选也不会释放。后续任务先确认 ComfyUI 队列空闲，再继续提交。未拿到 prompt ID 的未知提交还必须通过原任务 ID 找回提交；仅看到空队列或等待够久都不足以解除占用。找不回时保持阻塞，需检查 Windows 和 ComfyUI 的状态，不通过新请求、删库或清墓碑绕过。当前没有强制清空占用的客户端接口。

OOM、缺模型、缺节点和运行依赖变更各自失败，不自动重试另一个模型。已确定的成功/失败终态只保留一个结果；迟到完成不能覆盖超时结果或复活已删除任务。终态文件清理与占用记录、墓碑、工程备份分开管理。

确实无法找回未知提交时，操作人须先停止桥接，停止并重新启动对应 ComfyUI，确认旧执行已经结束且无人提交新任务，然后才可运行 `python tools/release_executor.py --data-dir data-comfyui --comfy-url http://127.0.0.1:8388 --confirm-comfy-restarted`。工具要求独占桥接数据目录、原任务已终结以及 ComfyUI 空队列；它依赖操作人明确确认重启，不把空队列自动当作重启证据。它不取消任务、不改终态、不删墓碑，完成后再启动桥接。

## Mac 与 iPad 接入交接

不需要增加请求 part 或 metadata 字段。选择器从 `GET /v1/capabilities` 读取 `presets`，默认使用 `defaultPreset`；旧客户端继续选择第一项。每项至少显示名称、实验标记、许可用途、输入限制与检查状态，禁用 `enabled=false` 或 `configured=false` 项。切换项后调用 `GET /v1/backend/status?presetId=<id>`，检查 HTTP 与 `ok`，缺依赖时只禁用该项并显示缺项。

`installed`、`structuralPreflight`、`gpuSmoke`、`qualityAdmission` 必须分别理解。结构检查通过不能显示“效果已验证”；目录中的 `not_checked` 与状态接口的 `unverified` 均表示未验证。固定 controls 不开放无效滑杆或发送未知参数，输入裁切采用全局和预设中更严格的限制。多参考、多候选与取消按钮继续关闭。

iPad 继续提交 committed 快照：变换、图层蒙版、混合和组透明度已烘焙进 image；编辑选区单独进入 L8 mask。结果按原 crop 作为独立新层；原线稿保留为独立图层。生成期间继续绘画、旧版本候选确认、防重复应用和单次撤销逻辑保持不变。不要把模型结果直接覆盖原线稿，也不要再次乘选区或原图层蒙版。二分/四分的严格量化由独立离线操作实现，不能用模型工作流冒充确定性分阶。

## 本次验证记录

2026-10-21 在 Windows / RTX 5080（16303 MiB）上完成最终桥接测试：**190 项测试、176 个子测试通过，0 跳过**。覆盖 V1 重放/删除、冻结与依赖变化、预设故障隔离、队列预算、超时占用跨重启和删除保留、迟到结果保护、错误连接恢复等。PR4 启动器兼容组合另有 33 项测试、38 个子测试通过；没有把 Mac 或历史测试计入本次数量。

在独立 ComfyUI v0.42.0 实例上，四类任务 × 三个合成主题 × 两个种子 × 768/1024 两档，共 **每预设 48 项、合计 144 项真实 GPU 请求全部成功**。输入、crop、结果摘要、straight alpha、遮罩范围和选区外合成保护检查通过。每档 24 项新请求的端到端中位耗时如下，包含上传、排队、核验、生成及下载，不能视为 SLA：

| 固定预设 | 成功数 | 768 输入中位秒数 | 1024 输入中位秒数 |
| --- | ---: | ---: | ---: |
| Klein 4B FP8 / 4 steps | 48 / 48 | 5.22 | 5.23 |
| Qwen 2.1 INT8 / 25 steps | 48 / 48 | 10.23 | 15.27 |
| Qwen 2.1 Turbo / 8 steps | 48 / 48 | 7.23 | 8.25 |

每 0.5 秒采样的整卡已用显存最高 15783 MiB，包含其它程序和先前模型缓存，也可能漏掉瞬时峰值，不能据此推算某模型的最低显存。原 ComfyUI 进程继续保留，本次没有强制制造真实 OOM；OOM 分类与恢复竞争使用自动测试覆盖。矩阵执行顺序为 Turbo → Qwen → Klein，包含缓存与切换，不是控制所有变量的冷启动基准。

矩阵完成后又补充了运行参数和连接绑定保护，因此重新启动独立 ComfyUI 与最终桥接代码，各预设再实际生成一次，**3 / 3 成功**。768 输入的 Klein 进程冷启动首请求为 10.44 秒，切到 Qwen 为 16.50 秒，切到 Turbo 为 7.66 秒；操作系统文件缓存未清空，这不是磁盘冷启动测量。图与权重未更换，完整图/权重/源码/依赖摘要及最终桥接源码摘要保存在[脱敏验证记录](validation/windows-presets-v02-20261021.json)。

**工程与 GPU 验证通过，绘画质量准入仍待人工审阅。** 样本是原创合成图，不代替用户代表画稿；iPad PR7 的变换、蒙版、候选确认与撤销仍需 Mac 真机联调。没有因此开启默认 Qwen、变更日常配对或部署到原 iPad 服务。capabilities 的验证状态也不会凭这份文档自动提升，避免把另一台机器的测试当作本机已通过。原稿、运行日志、配对文件和生成结果留在私人测试目录，公开仓库只保存代码与脱敏结论。

## 升级与回退

1. 停止接收新任务，等待旧队列结束，并确认 ComfyUI 队列与未知提交都已对账；桥接超时不能作为排空证据。
2. 停止桥接后完整备份原数据目录、配对信息及本机启动配置，记录源码和 ComfyUI 版本；SQLite 数据库及 WAL 相关文件须来自同一停机时点。备份保持私有。
3. 新实例先使用独立数据和运行目录验证；正式切换时保留原 token、任务数据库及墓碑，只允许一个桥接进程拥有同一数据目录。
4. 本增量对数据库做增量迁移。升级后没有快照的旧未提交 GPU 任务明确报 `legacy_snapshot_missing`；已有 prompt ID 或提交记录的任务继续恢复，不能按新图重跑。因此优先在升级前排空队列。
5. 回退前再次停止新接收并完成对账，保留升级后的完整数据。旧服务不认识执行快照和推理占用，**不能直接读取仍含排队任务或未释放占用的升级后数据库**。含删除墓碑的数据也不能交给不支持墓碑的更旧版本。
6. 恢复升级前备份须先在隔离目录核对升级后新增请求、结果和墓碑；不能直接丢弃新记录后让客户端重发，否则可能复活请求。优先回退到保留新读取与恢复语义的兼容代码；尚未完成差异处理时保持原服务停止或使用保留的独立旧环境，不混用两套任务数据。

完整接口字段与错误处理以 [API v1](../ipad_bridge/docs/API_V1.md) 为准。
