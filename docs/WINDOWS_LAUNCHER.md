# Windows 启动器使用说明

Windows 绘画助手把 ComfyUI、桥接、模型与连接检查放在同一个窗口中。iPad 继续负责画稿编辑，Windows 提供真实 AI 生成和工程备份。

## 第一次使用

1. 准备 Python 3.12 或以上，安装时包含 Tcl/Tk。进入仓库的 `ipad_bridge/`，运行 `setup.ps1` 创建桥接环境并安装依赖。已有桥接环境可以继续使用；不需要在桥接环境安装 PyTorch。
2. 准备已安装的 ComfyUI 和 [桥接预设所需模型](../ipad_bridge/README.md#windows-安装和启动)。启动器不下载或安装 ComfyUI、模型。需要由启动器启动 ComfyUI 时，安装文件夹必须包含 `main.py` 和 `.venv/Scripts/python.exe`；其他安装布局可先用原来的方式启动 ComfyUI。
3. 双击 `ipad_bridge/Start-Windows.cmd`，点击“设置”，选择下表中的本机路径和局域网地址。已有任务与配对时，选择原来的任务数据文件夹，以继续使用同一套任务、工程备份和凭据。
4. 点击“保存并检查”，再点击“启动服务”。已有服务会先核对，匹配时直接复用；尚未启动的部分才会启动。ComfyUI 使用本机地址 `127.0.0.1`，iPad 只连接桥接。
5. 打开“配对文件夹”，将其中的 `pairing.json` 私下传给自己的 iPad 或 Mac，按 iPad 应用的配对入口导入。iPad 上再执行一次“检查连接”。

如果双击后提示找不到运行环境，先运行 `setup.ps1`，或在本机配置的 `bridge_python` 中填写已有环境的 `python.exe` 路径。若提示缺少桌面组件，安装含 Tcl/Tk 的 Python 后重新创建桥接虚拟环境；`pip install` 桥接依赖不会安装 Tcl/Tk。

## 日常操作

| 操作 | 行为 |
| --- | --- |
| 检查状态 | 只读取配置、网卡、配对及服务状态；不启动服务，不改写配对，也不提交 AI 任务 |
| 启动服务 | 检查冲突，复用现有服务，补齐尚未启动的服务，并准备当前地址的配对文件 |
| 设置 | 保存本机路径、地址和端口，再检查连接；保存设置本身不会重启服务 |
| 复制地址 | 复制桥接连接地址，不包含访问令牌 |
| 配对文件夹 | 打开含 `pairing.json` 的任务数据文件夹 |
| 日志 | 分别打开桥接日志和 ComfyUI 工作文件夹 |
| 关闭窗口 | 关闭状态窗口；已经启动的服务继续在后台运行 |

启动器不会自动升级或替换运行中的桥接。更新服务代码后，应在任务结束时按原来的管理方式停止旧服务，再启动新版本；同一套数据只运行一个桥接进程。

ComfyUI 启动较慢时，窗口可能先显示仍在准备。超时不会自动结束进程或再启动一份。先查看日志，稍后点“检查状态”；服务已经响应后继续复用。关闭窗口时，已经发起的启动操作也会继续完成。

## 本机配置

默认文件是 `ipad_bridge/launcher-private.json`，已被 Git 忽略；首次通过“设置”保存时创建。它保存本机路径和地址，配对令牌仍保存在原任务数据文件夹。不要把本机配置、配对文件或日志加入公开仓库。

| 字段 | 界面含义 | 填写方式 |
| --- | --- | --- |
| `bridge_python` | 桥接运行环境 | 已安装桥接依赖的虚拟环境 `python.exe`；默认是本目录 `.venv/Scripts/python.exe` |
| `comfy_install` | ComfyUI 安装文件夹 | 包含 `main.py` 的现有安装目录 |
| `models_dir` | 模型文件夹 | 包含 `diffusion_models`、`text_encoders`、`vae` 等子目录的现有模型根目录 |
| `data_dir` | 任务与工程备份 | 使用原来的真实后端数据目录，默认是本目录 `data-comfyui/` |
| `runtime_dir` | ComfyUI 工作文件夹 | 保存启动器所启动 ComfyUI 的输入、输出、缓存和日志，默认是本目录 `data-comfy-runtime/` |
| `lan_address` | Windows 局域网地址 | 当前连接 iPad 所在网络的物理网卡 IPv4 地址 |
| `bridge_port` | iPad 连接端口 | 默认 `8190` |
| `comfy_port` | ComfyUI 本机端口 | 默认 `8388`；复用现有 ComfyUI 时填写其实际端口 |

所有路径使用绝对路径。任务数据和 ComfyUI 工作文件夹必须分开，不能互相包含。两个端口必须不同，并在 `1024–65535` 范围内。修改这些设置不会移动原数据，也不会自动改动已有进程的运行参数。

下面仅为配置示例，需替换成自己的实际路径和地址：

```json
{
  "bridge_python": "C:/Compositor/ipad_bridge/.venv/Scripts/python.exe",
  "comfy_install": "C:/ComfyUI",
  "models_dir": "C:/ComfyModels",
  "data_dir": "C:/CompositorData/bridge",
  "runtime_dir": "C:/CompositorData/comfy-runtime",
  "lan_address": "192.168.1.100",
  "bridge_port": 8190,
  "comfy_port": 8388
}
```

## 选择地址与重新配对

“设置”会列出活动网卡并标出虚拟网卡。只有一个合适的物理局域网地址时可以给出建议；已有地址仍有效时优先保留。存在多个物理地址时，请自行选择 iPad 所在的 Wi-Fi 或有线网络。

VPN、TUN/TAP、虚拟机和 `198.18` 网段不会被自动推荐。地址列表读取失败时可手动填写，并检查 Windows 网卡读取权限；启动前仍需确认该地址属于当前物理网卡。

换 Wi-Fi、重启路由器或地址分配变化后，原配对可能指向旧地址。先在“设置”中选择新地址并保存，再点“启动服务”。启动器会核对原凭据和现有服务后更新配对文件中的地址，保留原令牌、任务与工程备份。随后将新的 `pairing.json` 私下传给 iPad，重新导入。只点“检查状态”不会更新文件。

## 连接排查

| 界面提示或现象 | 处理方式 |
| --- | --- |
| 模型或节点未就绪 | 按界面缺项核对 ComfyUI、模型文件名和模型目录；查看 ComfyUI 日志。服务已启动不等于模型检查通过 |
| 端口占用 | 确认占用者是不是原来的服务。选择与现有服务一致的端口，或选择空闲端口；启动器不会结束占用进程 |
| 配对或数据目录不一致 | 重新选择原数据目录，保留原凭据；不要用新令牌覆盖旧凭据来绕过检查 |
| 无法核对现有桥接参数 | 检查服务使用的数据目录、真实后端、ComfyUI 端口和监听地址，并确认启动器有权读取进程信息 |
| 地址不在当前物理网卡上 | 重新选择当前 Wi-Fi 或以太网地址，保存后启动服务，再在 iPad 导入更新后的配对文件 |
| 启动超时或没有响应 | 查看日志并等待后再检查；确认进程状态后处理原因，不要反复启动多份服务 |
| 启动结果或进程身份尚未确认 | 先检查服务是否已经响应；仍无法恢复时，按下方“恢复未确认的启动记录”处理 |
| Windows 检查通过，iPad 仍无法连接 | 检查两台设备是否在同一局域网、访客 Wi-Fi 是否隔离设备、iPad 是否允许本地网络访问，以及 Windows 防火墙是否允许桥接的专用网络入站连接 |

启动器不会添加防火墙规则，也不会关闭防火墙。网络相关结果和提示用于定位问题；本机访问自己的局域网地址成功，只说明本机入口可响应，不能证明 iPad 到 Windows 的网络可达。最终以 iPad 的连接检查和一次实际任务为准。

ComfyUI 保持仅本机可访问；不要为解决连接问题将它暴露到公网。当前启动器使用受信任局域网内的 HTTP 开发配置，需要 HTTPS 时按 [桥接 README](../ipad_bridge/README.md#配对和网络) 使用原手动启动方式及正常证书校验。

### 恢复未确认的启动记录

启动器将启动过程保存在任务数据文件夹中的 `launcher-state.json`。如果创建进程后读取身份失败，或启动辅助程序超时，服务可能已经在后台运行。此时保留记录并阻止重复启动，是为了避免再开一份 ComfyUI。

1. 先点“检查状态”，查看桥接日志和 ComfyUI 日志。若服务已响应且检查通过，可以直接使用，无需重置记录。
2. 确实需要重置时，等当前启动操作结束，关闭所有启动器窗口。通过 Windows 任务管理器的“详细信息”和“命令行”核对进程，确认使用本机配置中数据目录、安装目录和工作目录的桥接、ComfyUI **都已停止**。关闭启动器窗口本身不会停止它们，也不能只凭端口暂时没有响应就认定进程已经退出。无法确定时，可重启 Windows，再确认这两个服务没有自动启动；不要结束其他项目的 Python 或 ComfyUI 进程。
3. 只有完成上述核对后，才把 `data_dir/launcher-state.json` 备份到本机私人备份位置，再将原文件移出任务数据文件夹。这里的 `data_dir` 是“设置”中选择的“任务与工程备份”路径。保留备份，不要提交到 Git。
4. 重新打开启动器，核对设置后点“启动服务”。启动器会重新记录新进程。保留原来的 `access-token.txt`、`pairing.json`、`jobs.sqlite3`、任务文件和工程备份；恢复启动记录不需要删除或重建这些数据。

## 命令行与开发检查

在 `ipad_bridge/` 中使用已安装依赖的桥接 Python：

```powershell
.\.venv\Scripts\python.exe -m launcher --config launcher-private.json --status
.\.venv\Scripts\python.exe -m launcher --config launcher-private.json --start
```

等价入口为 `python -m launcher --config launcher-private.json --status` 或 `--start`；`python` 必须指向正确的桥接环境。省略模式或传入 `--gui` 会打开桌面窗口。状态和启动命令输出 JSON，就绪时退出码为 `0`，仍有阻塞项时为 `1`；输出不包含配对令牌。

`--status` 用于只读检查；`--start` 会创建必要运行目录、启动缺少的服务并更新需要更新的配对文件。两者都不提交生成任务。自动测试运行 `python -m pytest -q`，使用 Python 3.12，不需要安装 ComfyUI、模型或显卡驱动。自动测试不能替代真实 iPad 跨设备验收。
